# Native bulk purchase overlay

Build using `.analysis-venv/bin/python tools/client_bulk_purchase/build.py --output-directory build/bulk58-composed-no-fieldptr-r1`. Add `--input-managed /absolute/path/Assembly-CSharp.dll` for serial overlays. The original fixed55 APK supplies references and native resources. This does not package or install an APK.

The helper is `HYJS.BulkPurchase.dll`, public API `HYJS.BulkPurchase.BulkPurchase.SelectQuantity(Component owner, string rewardId, int rewardAmount, string costId, long unitCost, int max, Action<int> confirm)`. A true return means the original quantity shell accepted the request. Cancellation never invokes confirm; max1 still requires confirmation. The caller owns final authority/revision/session validation.

Uses original ShopPage.batchBuyPref (cached page first, original ResourceManager fallback), original BuyShopItem widgets and callbacks. No replacement art or modern payment UI. All resource costs appear in the wrapping description; original first two cost icons remain native.

Original IExtensible unknown-field storage retains all Main fields/RIDs and keeps FieldPtr/MethodPtr absent. No new ProtoMember field is injected. ShopItem/ActivityShopItem tag100 repeated BaseResource curves encode the authoritative full price at quantity n at index n-1. Discounted legacy responses without a curve are capped to1. OpenServer107/108 and UF requests use optional int tag100; absent0 preserves old default1. Actual shipped protobuf-net serialization and both unknown curve roundtrips are tested against original message classes by ProtoProbe, including default omission and unchanged old field bytes. This old runtime merges repeated values with scalar GetValues<BaseResource>; GetValues<List<BaseResource>> preserves2/3/5 and is used by the helper. Requests use AppendValue<int> exactly once, reject repeated append and counts outside1..100. Curve reads reject more than100 or invalid resource entries.

UF pending is scoped to page/player/playerData/session bytes/UF room. A20-second unknown-result deadline requests an original authoritative list with5-second throttling and keeps the purchase locked until SetItem. It never resends the purchase. Page disable or scope change clears only old scoped pending. Successful own-player broadcast clears the SKU. No generic socket error is treated as success.

HTTP callbacks retain original timeout/retry behavior. HTTPManager singleton result1 deliberately preserves its last handler for the original timeout dialog retry. Scoped pending survives closing/reopening custom shells. Existing BuyShopItem.Show and added ShopBatchBuy.DoOpen hooks request a native authoritative refresh when idle. Unlock requires a different quote object, no in-flight HTTP, and a replaced last handler; callbacks release their own record. Role/session changes discard old scope. Refresh uses proven ShopPage.UpdateCurTab, UnionShopTab.Init, or SevenDayPage.AskServerActivity. Activity panels without a proved refresh API retain the original retry path and show the pending-result message. No global handler clearing or timed purchase retransmission.

Build validates original target CIL pins, all non-target method raw CIL relative to input overlay, original547 engine methods and EH, old definition signatures/field RIDs, zero added fields and original protobuf unknown-field transport, and absence of helper-scoped ModuleRef for Main types. Real Unity rendering and transport flows require parent device acceptance.
