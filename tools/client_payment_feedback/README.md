# Payment feedback managed overlay

Assembly `SoulFlowerPaymentFeedback`, class `HYJS.PaymentFeedback.PaymentFeedback`, persistent Unity object `HYJSPaymentFeedback`. Only original `UI.ChargeData.ChargeBegin(string,string,string)` is replaced by a four-argument bridge (instance plus original arguments). Original platform callback bodies remain byte exact; new flow uses attempt-bound callbacks instead of their global pending lock.

Java integration requires `com.hyjs.wallet.WalletActivity.checkRechargeBalance(String attemptId,long amountCents)`. It must asynchronously validate the authenticated current server wallet and send `UnitySendMessage("HYJSPaymentFeedback","OnRechargeBalance", attemptId+"|ready")`, `|insufficient`, or `|error`, dropping changed Java auth-generation/origin responses. This interface supplies no payment or reward success.

Each attempt snapshots player/session bytes, UUID, generation, and 30-second realtime deadline. Preflight insufficient/error creates no order. Generate is sent once using original fields and NetAPI stamp mechanism; strict correlated generate reply creates one read-only query. WAIT releases local UI and retains server pending history. Only matching order/product and exact PAY_STATUS_SUCCESS runs original ChargePage refresh semantics and one success notice. Original NetAPI processes the server SCPlayer normally. Stale callbacks never mutate current attempt. Timeout does not cancel server orders or repeat payment.

Build with project analysis Python and `build.py --base-apk ... --expected-sha256 ... --output-directory ... --tool-root /Users/lirui/LR/hyjs`. Uses actual APK mscorlib/UnityEngine/main references and C#3; verifies all 547 engine bodies and every non-target raw body unchanged. `verify_logic.py` executes the actual helper source against minimal Unity/network doubles on net8. This is static/source boundary validation; phone, Java callback transport and real protocol remain parent integration checks. No APK packaging or install.
