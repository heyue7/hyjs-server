# 不同竞技玩家的间隙锁等待

服务器北京时间复验暴露可重复等待：首个角色已有真实结算历史，持有下一场独立名次的事务不提交时，另一角色的结算卡在 `create p11_arena_fight_settlements`。本机MySQL会话/默认隔离均为REPEATABLE-READ。原始失败见 mysql-beijing 与 mysql-gap-diagnostic，未改变超时或断言求通过。

原入口先锁实际参与角色，再对尚不存在的 `(player_id,stamp)` 回执执行 FOR UPDATE。前者已经串行同角色请求，后者会锁住相邻范围，妨碍无关角色的 INSERT。改为普通MVCC读取；主键唯一约束、角色锁、同stamp请求摘要校验和原子提交保持。匹配快照也是不可变输入，读取时去除范围写锁，保留归属、时间、名次、配置和摘要复核。

新回归先用真实权威胜利建立历史，再让另一场争不同名次，要求第二人能在第一人的事务提交前完成。原同一虚拟位唯一占用/失败回滚/能量守恒、历史回执和截止规则也保留并通过。修复不改变数据库隔离级别，不增加全局互斥、计数器或锁表。

七项相关北京时间InnoDB回归通过；另在两个新库重复独立位/同位仲裁，两项再次通过。抽象规则已加入后端AGENTS，提醒父行互斥下避免对不存在的子行再取范围锁。
