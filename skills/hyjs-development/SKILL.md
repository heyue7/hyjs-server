# HYJS 工作方法

本文件规定执行方法；技术约束在根及后端 AGENTS，业务与当前进度在 plans。按需读相关材料，不为无关改动加载全部业务历史。

## 1. 固定范围与事实

- 先区分分析、方案、规则维护、实现或发布，继承已有授权，不自动把文档任务扩成开发。
- 从 `plans/README.md` 定位当前相关计划；需要查范围时再查工作索引及全量审计。版本、数值、业务决定和现场证据只写 plans/analysis，不回灌稳定规则。
- 明确触发条件、计时起止、环境、覆盖范围和验收阈值；区分已接受要求、建议目标和实际结果。首次反馈、服务端处理、资源加载及完整可用分别测量。
- 实施前核当前源码、运行版本与可复用证据。涉及规则、生命周期或验收口径时才查对应业务合同。
- 有截止时刻即记录绝对时间和时区；预算包含验证、发布、清理与汇报。业务与验收绑定服务端权威时间/时区，沟通沿用户指定时区，不从开发机默认时区推断。

## 2. 设计后实施

1. 主代理沿真实入口到持久化/回包确定第一处偏差，列明改动文件、归属、锁序、迁移、恢复和最短验收；先去掉无关工作，再考虑表结构或基础设施。
2. 性能改动先画出主体与资源边界，识别事务、公共锁、循环查询、大字段编解码和提交后重复工作；按 [性能检查](../../hyjs-server/docs/development/database-performance.md) 记录同输入基线。
3. 修复覆盖入口、成功提交、失败回滚、重复请求、退出与恢复；复用已有接口、账本和迁移机制，不并行制造另一套权威状态。
4. 单个断点取证约 15 分钟；两次尝试没有新事实就切换工具或取证方式，其余独立工作继续。新证据才扩大修改范围。
5. 同一请求/事务复用已读取对象和不可变验证结果；回滚、重试和新事务重新读取可变状态。代码减少工作量，保持原授权、来源验证和原子提交语义。
6. 界面改动沿用现有组件与交互。端侧异常先核实际加载的制品、输入/回包和等待状态，修复对应分支，不用提示或蒙层代替业务完成。

## 3. 按风险合批验证

- 先列影响范围、可复用证据及新增检查；按格式/编译、功能、交易恢复、实机和集成分别报告完成状态。
- 独立文件先做必要定向检查，共享核心合批编译、vet、构建和联合回归；不为文档或 runner 变化重复构建产品。
- 锁、索引、迁移和资产幂等使用真实 InnoDB；兼容库与模型结果只说明其覆盖范围。失败保留原记录，区分产品、夹具、环境和证据，不能弱化断言求通过。
- 对比固定输入、规则版本、并发和环境，记录 SQL/事务、解码/编码、锁等待、CPU/分配和端到端耗时。慢日志最大值、局部基准和瞬时资源占用不外推为容量或全部请求分位数。
- 实机只验新范围的关键链及必要恢复代表，先模型/协议验证，再合批打包一次；新增失败以实际断点决定复验。探针限定采样时间/数量，验前核账号归属，验后恢复现场与资源。

## 4. 协作与资源排队

- 遵守根 AGENTS 的执行代理约束；派发包含背景、授权、基线、文件所有权、具体步骤、验收和资源约定。主代理保留设计、审查和集成职责。
- 同一文件保持一个写入者；公共入口、迁移注册和最终集成指定负责人。代理发现方案外问题时带证据返回，不自行新增设计。
- 编译、数据库回归、实机和发布按真实资源冲突排队；共享数据库使用隔离库和租约，设备同时一人操作。
- 交付带实际结果、证据、剩余项和资源释放情况。等待代理时主代理推进独立工作，不让多个任务重复取证同一问题。

## 5. 发布与收尾

- 仅在已授权范围发布；先固定源码/制品和检查结果，沿现有入口核前提、配置、迁移就绪和恢复路径，发布后核实际运行版本及关键行为。
- 生命周期、备份及生产操作限制按相关 [运行合同](../../plans/runtime-contracts.md) 执行；不因加载 skill 自动授权外部通信、生产资产变更或服务重建。
- 及时停自有进程、释放测试库/连接、设备转发和探针，清理无引用打包中间物；保护共享资源与当前制品。
- 按 [批次记录](references/batch-record.md) 记录实现、验证、发布和资源状态。最终回答独立说明已完成、未完成、实际上线状态和交付路径。
