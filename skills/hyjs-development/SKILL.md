# HYJS 工作方法

技术约束遵守根/后端 AGENTS，业务、版本、数值、进度与现场证据只写 plans/analysis。按需读取，避免重复加载历史和规则。

## 实施

- 继承已有授权，区分分析、规则、实现与发布；从 [计划导航](../../plans/README.md) 只读相关计划，范围不清再查工作索引/全量审计，涉及生命周期或验收再查 [运行合同](../../plans/runtime-contracts.md)。加载 skill 不授权通信、生产资产变更或服务重建。
- 先核源码、实际运行版本与可复用证据，沿入口→持久化→回包找第一处偏差。主代理定文件归属、接口/表、锁序、迁移、恢复与最短验收，再按根 AGENTS 委派具体步骤、审查集成；单项小改直接完成。
- 优先现有机制和成熟的最小解法，先删重复工作再考虑表结构、缓存或基础设施；不用假设故障堆补丁、抽象、兜底或新权威状态。复用接口、账本、迁移和组件，保留授权、来源验证及原子提交。
- **Let it crash**：业务层只处理有明确语义的预期失败；未知错误携带上下文向既有边界返回，终止本次操作、回滚事务并释放资源。恢复归请求/会话/任务监督边界，重试只用于已知瞬态错误，明确幂等和上限。Go 沿错误返回与现有恢复机制执行；不得吞错、伪造成功、逐层猜测修复，也不为套用理念新增进程重启或无边界 panic。[依据：Erlang 错误隔离与监督恢复](https://www.erlang.org/doc/system/sup_princ.html)。
- 性能先核主体/资源、事务/公共锁、循环查询、大字段编解码和提交后重读，按 [性能检查](../../hyjs-server/docs/development/database-performance.md) 取同输入基线。同请求/事务复用已读对象和已验证不可变结果；回滚、重试、新事务重新读取可变状态。
- 修复覆盖真实入口、成功提交、失败回滚、重复请求、退出与恢复。端侧先核实际制品、输入/回包和等待分支，沿现有交互修复业务完成；提示/蒙层不能充当完成证据。
- 单断点取证约 15 分钟，两次尝试无新事实即换工具/方法并推进独立项；仅新证据支持扩大范围。有截止时记录绝对时间/时区，预算含验证、发布、清理和汇报；业务/验收用服务端权威时区，沟通沿用户时区。

## 验证与交付

- **以能裁决问题的最小证据集为准。** 先列影响和可复用证据，只补本次行为与关键不变量的缺口；不为可逆低影响/文档改动写测试，不写复刻实现或匹配措辞的测试。通过必要检查即交付，只有新增修改、失败或未解风险才扩大/重复验证。
- 独立文件做必要定向检查，共享核心合批编译、vet、构建和联合回归；文档/runner 改动不重复构建产品。锁、索引、迁移、资产幂等用真实 InnoDB，兼容库/模型只证明其覆盖范围；保留失败记录，区分产品、夹具、环境和证据，不弱化断言求通过。
- 性能比较固定输入、规则版本、并发与环境，按实际瓶颈记录 SQL/事务、编解码、锁等待、CPU/分配及端到端耗时；分清首次反馈、服务端、资源加载和完整可用，区分已接受阈值、建议和实测。慢日志最大值、局部基准、瞬时资源不外推容量或整体分位数。
- 实机只验新增关键链与必要恢复代表，先模型/协议再合批打包一次；失败按实际断点复验。探针限时限量，验前核账号/制品/前台归属，每次设备输入前复核前台，变化即停；验后恢复现场。
- 同文件单写入者，公共入口/迁移注册指定负责人；派发含背景、授权、基线、文件/资源归属、步骤和验收，方案外问题带证据返回。编译、数据库回归、实机、发布按冲突排队，数据库用隔离库/租约，设备独占；等待时推进独立项，避免重复取证。
- 仅按授权发布：固定源码/制品/检查结果，核现有发布入口、配置、迁移就绪和恢复路径；发布后核真实版本及关键行为。及时停自有进程、释放库/账号/连接/转发/探针并清理无引用中间物，保护共享资源及当前制品。
- 按 [批次记录](references/batch-record.md) 合并实现、各层验证、发布和资源状态；最终说明实际结果、证据路径、未完成项与实际上线状态，不用测试数量代替业务完成。
