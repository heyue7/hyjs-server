# 第二轮性能优化收尾

状态：性能实现、隔离回归与关键首领实机链通过，尚未部署；继续接手已授权遗留修复后统一发布。沿用首批 `ef0eaac`，服务器业务和测试以北京时间为准。第一轮线上基线仍为 `3fb495f`，不能将本地通过写成已上线。

## 实施

- E3：去掉进程级场景写门。成员保护按数据库连接池、角色和实际场景/线路建立有引用计数的局部锁；不借服务对象或 SQL 中没有的区服字段制造假隔离。稳定普通移动和公会领地移动只保护本人；成员变化只排他保护源/目标房间。自动选线先发现候选，再锁中选房间重读容量，最多 34 次尝试。实际同线人数上限、沙漠偏好及 20 人硬上限保持。
- 进入、退出、换线、旧会话断线与运营容量修改共用上述真实竞争域。原资产/回执事务、P8 采集换线限制及 PVP 判断保留。广播先固定接收者，释放房间锁后沿原单连接队列送达。世界/场景聊天、语音、HP、福袋、交易、首领投影和 PVP 仅保护实际参与角色。
- A1：夺宝扫荡每个事务尝试只读取/解码已锁真人一次，子场和投影使用当前对象。未选中候选继续 MVCC；新参与者仍整批回滚并重新排序取锁。恢复后消费基线与真实持久化基线分开；祈福、阵位和野外 HP 投影复制必要字段。每场原 P6、能量/碎片停止、原子保存和冷回执不变。
- F3 沙漠：原 TCP 串行处理下，以原心跳的独有 echo 确认在途 Start 已处理，再查 active/恢复已冻结战斗。HTTP 的 active=false 单独不能证明未接纳。15 秒后不重发 Start；三次 echo 重试后进入原重连流程。回包绑定连接 epoch、会话、房间及场景代次，恢复只投递经原接口核验的同一 Start。
- 重连：替换连接先关闭旧连接并等该连接正在执行的请求结束。排队的新连接心跳完成后再进行发现；只等待同一角色的旧连接，其他角色继续执行。
- F3 觉醒：包装原 81009 HTTP 回调和等待协程，绑定会话、房间、战斗对象及怪物 GUID；正常处理和播放继续使用原逻辑。超时、失败及资源异常清理本次等待，沿原重登入口恢复；晚包、重复回调和旧协程不能修改新场景。同一怪物已接纳战斗沿服务端已有 pending 分支重用。

- 战斗计算两层调用继续复制可变角色与协议元数据，仅复用已冻结且只读的规则表；保留原深复制入口供规则写入者使用，保留有限值及 JSON 校验。固定实际规则表的克隆基准从 13,885,480 B/op、29160 allocs/op 降至 5400 B/op、80 allocs/op，仅代表该克隆步骤。竞态、原引擎固定输入及完整输入不变断言通过。

本批无新增表、服务或基础设施。首批已提供档案 codec、身份小列、竞技分配器、生成列/索引、P6 复用、具体 Boss MVCC 和秘境目录优化，统一随本次发布。B2/G 的跨请求规则缓存、热位置拆表和候选投影仍按条件决定；当前不为未证明的收益扩表。对象存储试点依赖厂商/内网合同，活跃资产仍在 MySQL。
