## 已实现的边界

- 移动确认鉴权只取五个身份列，继续核会话、账号撤权、客户端版本和区服。
- 压缩人物读取直接展开人物片段，去掉完整扩展 JSON 的重编码中转；保存仍沿用原恢复基线与有界压缩格式，未加全局角色缓存。
- 同一请求只保留最后一条完整验证过的不可变 P6 输入，标识、版本、摘要和压缩字节都相同才复用。原来源、终局、状态和回执校验继续执行；通用资格不再重复验证。
- 竞技日常查询只准备本人和最终少量对手。名次元数据分批查询，黑名单批量查询，不解码/更新全服档案。历史迁移和全名册重建仅在启动维护中分批读取。
- `profiles.player_level` 是数据库生成列，原始 SQL 更新同样维护投影；索引为 `(server_id,player_level,id)`。无业务层双写资格字段。
- 稳定竞技规则共享读；`p11_arena_rank_allocators(policy_id,next_rank)` 只负责首次分配。新成员从已提交资格快照登记，不取得其他角色资产锁；匹配与实战核当前等级/阵容。截止维护先回滚普通尝试，再独占处理，最多三次尝试。
- 虚拟名次竞争保留 position 唯一约束：同位冲突整笔回滚并要求刷新，不重复扣费；不同名次可以并行提交。
- 扫荡只锁已经实际选中的真人。需要新的参与者时整批回滚、重新按 ID 排序取锁再复核，保留 1/5 次、掉落、能量和整批回执语义。历史回执不再预解析对手当前库存；原归属和不可变战斗来源仍验证。
- 稳定的普通首领投影走 MVCC；缺失、换代、伤害、击杀仍按原具体首领主键加锁。沙漠开战复用已经编码的输入做压缩和摘要，去掉保存时第二次完整编码。
- 秘境状态目录只读 id/player，个人日状态一次读取，续局只读类型/章节。开战与结算保留原恢复和写事务。
- 福袋查询/抢取及交易过期清理不取全场景写门。投放上限只按真实计数域（当前数据库、场景、线路）短串行，袋子唯一领取及个人资产继续由各自行锁保护；投放锁在提交/回滚后、广播前释放。

资格兼容发现每次只投影最多 64 个缺失/重新合格角色 ID；后台沿 keyset 游标继续处理，损坏候选不会永久遮住后面的角色。最终匹配另读当前少量对手，未增加新的角色缓存或数据库服务。

## 迁移和回退

- 生成列/索引迁移可重复，旧库单独补列或索引；非法 JSON/非整数/越界等级得到 NULL，不伪造资格。SQLite 仅验证兼容，生产语义由 MySQL 验证。
- 启动时在竞技规则独占窗口，沿原历史证据迁移虚拟位，从旧 NextRank、分配器和真实最高位核定计数，再发布分配器。已有名次、首达收益和身份域不重排。
- 回旧程序前先停止新名次分配，锁住 policy 与 allocator，令旧 `p11_arena_policies.next_rank` 至少等于分配器及真实 `MAX(position)+1`，核正名次唯一后再切旧程序。新列、新表可以保留，不能只切回旧二进制使用过期计数。
- 本批不改变活动/钱包格式，不新增 MongoDB、Redis 或对象存储热路径；未对生产执行迁移、奖励测试或备份。
