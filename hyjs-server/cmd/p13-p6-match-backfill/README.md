# P13 P6 match归属回填

仅显式维护使用；服务请求和启动不会运行回填。先部署/验证包含p13_match_id和索引的P6模型迁移，保留必要备份，核本机共享服务/生产授权。工具用InitExistingGameMySQL连接，不创建库、不修改结构、不删除记录。

从环境变量读取 HYJS_MYSQL_HOST / USER / PASSWORD / DATABASE；不在命令行传密码。checkpoint绑定host+database摘要，禁止把另一库的断点用于当前库。

在hyjs-server目录，使用已固定源码构建的工具：

```sh
rtk go build -o /明确的本次工具路径 ./cmd/p13-p6-match-backfill
rtk proxy /明确的本次工具路径 --apply --checkpoint /私有目录/p13-scope.json --batch 4 --max-batches 1
```

默认每次最多4条完整冻结输入，支持1..8；每批ID升序有界读取。验证ID来源键、原InputHash、冻结表/引擎/角色闭包和三个具名P13 source的唯一match事实后，使用ID+InputHash+空归属CAS回填。每个成功批次原子保存断点；失败输出row ID及原因，断点仅推进到最后成功行，失败行保持原样。再次同命令恢复。中断发生在回填提交而断点落盘前时，下次按空归属查询跳过已完成行。

未归属或损坏历史不会被删掉、不会默认赋予当前比赛；相关玩家的有战结算继续待决。应修复可证数据/恢复必要备份后重跑，不能跳过坏行来冒称历史认证完成。新捕获已经同事务写归属；维护游标只针对部署前旧行。若有人额外导入空归属旧行且ID小于断点，需要用新的checkpoint从头验证，旧数据仍由结算的空归属检查保护。

输出不含凭据和原输入。工具不发布奖励、不改存档、胜负或录像内容。运行后核空归属数量、回填断点、失败行及当前交付工具引用，再按项目磁盘规则清理可再生工具构建物。
