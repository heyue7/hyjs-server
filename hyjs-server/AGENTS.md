# 后端研发约定

继承根 [AGENTS](../AGENTS.md) 与项目 skill。本文件只保留技术约束；实现检查按需读 [性能检查](docs/development/database-performance.md)，业务口径与生命周期按需查 plans。

## 1. 技术与代码结构

- Gin/Gorm，Go 固定 1.27.2；生产 MySQL/InnoDB。SQLite 仅用于迁移源或显式隔离兼容验证。优先复用现有基础设施，新增服务须有已测收益、资源预算和一致性边界。
- handler 负责绑定、清洗和入参校验；service 负责业务与编排；model 放 DTO；db 放表模型和 SQL。表模型显式 TableName 与字段标签，结构 SQL 放 db/sql，每表一文件，seed 用同 basename 加 .seed.sql，与模型保持一致。
- 同领域入口、回调、失败及恢复就近组织；独立子域再拆分。包级配置键、锁键、超时和错误模板放 constUtil；不为小改引入通用框架。
- 多变量声明优先 var 块；沿用调用链 ctx 和已有 tx，脱离取消且保留 values 使用 context.WithoutCancel。数据库沿用带 ctx 的连接。
- gofmt、受影响验证、合批编译/vet/构建；共享核心与最终交付按影响执行联合回归。依赖使用 go mod tidy，不手改 go.sum。

## 2. 协议、接口与错误

- 恢复的原消息、字段、编号和数值类型保持；原二进制协议不套通用 DTO。新增管理接口使用独立 Request/Response、JSON 小驼峰、SQL 下划线，返回展示所需字段，不暴露 db model。
- 自定义 ID/状态整数优先 int64，原生成类型不改；必填、枚举及互斥条件在 handler 明确校验。导出 DTO/字段和 handler 写可生成 Swagger 的注释。
- handler 返回 error，由 wrapper 统一处理；成功返回既有业务包装。沿用集中错误码，参数/系统/业务错误不混用。
- 内外 HTTP 使用现有 httpClient 入口及地址池；配置遵守环境优先与既有回退，新增配置同步声明和环境模板。

## 3. 数据归属与表设计

- 先核主体、基数、生命周期、实际读写和锁序。固定一对一、同主体且一起读取的小标量优先合并；独立高频写、冷热、历史、一对多和账本按真实边界分离。
- 账号身份、认证、当前资源、可变资产、公共目录和历史证明职责清楚；不把钱包/流水/历史塞进大档案，不建类型驱动的多态巨表。
- 聚合止于独立竞争的资源单元；不能把多个主体/资源合成一个公共可变 JSON。稳定配置与号段分配、运行计数分离，避免日常读者争用同一写行。
- 需要筛选、排序、索引和独立更新的热字段用关系列/行；同主体低频小扩展和不可变快照可保留结构化负载。存储格式不替代归属和事务设计。
- 索引覆盖归属及真实 WHERE/ORDER BY，唯一约束承载真实竞争；使用列级更新，禁止 Save 旧整行覆盖他人变更。查询按需选列、分页及批量关联，禁止 N+1；单 SQL JOIN ≤3。
- 派生投影有明确权威来源、完整写入覆盖、同事务更新和就绪核验；仅有列/索引不等于回填完成。遗漏候选不能仅靠最终校验补救。

## 4. 并发与事务

- 个人请求按主体隔离；只有规则要求共享的状态才互斥，锁键匹配唯一约束或计数查询的实际竞争域，不能用进程对象身份划出不存在的存储隔离。禁止为便于编排让个人事务先取得全局写门。
- 业务日和截止使用服务端权威时钟及时区；测试进程显式绑定同源时间，禁止依赖开发机默认时区。存储时间、真实时间和可调整业务时间各守原契约。
- 纯查询优先 MVCC；稳定规则仅在受理/停用边界需要时共享读，首次发布或真实变更才排他。查询不顺手修复全量名册、清理他人状态或执行历史补结。
- 不存在行的锁定读取须核实际间隙锁范围；原子创建优先用真实唯一约束，已有父行互斥时不再用子行范围锁重复保护幂等。
- 先发现参与集合，再按固定顺序取得必要行锁并复核；集合/版本变化时回滚整个尝试后重读重锁，禁止不受控锁升级或持锁补拿逆序资源。错误重试有界且不泄露回滚结果。
- 公共内存锁只覆盖最小元数据快照/变更；不包住数据库长事务、重计算或网络写。发送队列、超时和背压按连接隔离，跨资源迁移固定取锁顺序。
- 保留资产、转移、幂等回执及结果的原子性；唯一键冲突按业务语义裁决，不靠放宽约束或重复发放解决。通知只在成功提交后发送。
- 锁内避免外部调用、磁盘上传、密码计算和无关重活。计算移出事务须先保持受理、冻结、截止与重放合同，不能只移动等待或异步丢写。

## 5. 请求成本与状态复用

- 同事务的锁定对象只读取/解码一次并传递复用；原始持久化基线与业务恢复后对象分开。回滚、新事务和权限状态变化按需要重新读取，可变快照不跨请求盲用。
- 同请求按 ID＋摘要＋版本复用已验证的不可变输入/结果；各业务来源、状态和回执检查继续执行。规则表可只读复用，可变实例和随机状态必须隔离。
- 无变化不 UPDATE，仅写变化列；继续减少无关入口的大对象展开、重复编码和重算。恢复基线、到期及迁移产生的真实变化不能被省略。
- 高频路径不反复检查表结构、全库扫描或整目录重建。配置/缓存按库与版本隔离、有界、更新后可见；不新增全服热点键来代替数据库热点。
- 压缩与兼容处理有长度界限、原文摘要和损坏拒绝，避免解压→重编码→再解析的无用中转；存储和协议各守原合同。
- UI 等待按请求/会话/实例归属，失败、超时及晚回包有明确恢复终点；客户端第一反馈、服务端完成和资源可用分开验收。

## 6. 迁移、生命周期与资源

- 存量迁移可重复、中断恢复，核来源/目标语义、唯一约束、所有写入口与回退；普通请求不承担回填、压缩全扫、清理或表空间重建。
- 先减少重复写和大字段放大，再处理到期且无引用负载。保留身份、摘要、结果、幂等和仍被消费的业务证明；显示期限、物理负载与证明保留期分别管理。
- 诊断日志按价值/频率分级，高频成功仅 debug；重复故障有界汇总，关键错误保留。轮转同时受时间、大小、数量约束且空闲可执行；不记凭据、原始帧或完整档案。具体周期由相关运行合同与部署配置落实。
- 数据库内存、连接、临时空间和容器限额整体预算；不靠扩内存、堆并发、关闭持久化或全局清空换取性能。备份/清理/日志由授权及原生机制管理，保护共享资源。
- 同输入记录查询/事务、编解码、字节、锁等待、CPU/分配和端到端耗时；并发/迁移用真实 InnoDB，覆盖失败、重试和冷恢复。局部基准不外推为整服提升。
