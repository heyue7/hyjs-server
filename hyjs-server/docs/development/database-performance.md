# 数据库与性能检查

本页为后端约定的按需检查，不存业务、版本或排期。

## 改动前

- 沿入口→鉴权→事务→回包画出真实调用链，分别计 SQL/事务、重复对象读取、编码/解压、计算及锁等待。
- 列主体、主键、独立资源、生命周期和读写频率；核聚合是否扩大互斥，配置是否混入共享计数。
- 固定输入、规则、并发、环境和计时起止；首次反馈、后端完成与最终可用分别记录。

## 审查实现

- 查询仅取所需列；候选先廉价筛选再批量加载，索引服务实际范围和顺序，单 SQL JOIN ≤3。
- 只锁必要主体和资源；参与集合先发现、有序锁定、锁后复核，重试丢弃整个旧尝试的输出。
- 同事务复用解码对象，存储原始基线与恢复对象分开；不同事务重新读。不可变验证复用按对象、摘要和版本精确限定。
- 去掉重复准备和公共排他区间后，再以证据决定投影/冷热拆分或缓存；新增投影先证明所有写入覆盖和就绪。
- 无变化不写，变化只更新相关列；旧结构、压缩原文/摘要、权限、原子结果和冷恢复保持。
- 后台维护采用索引游标、限定批次和短事务，支持重启/中断；回退核新旧数据是否仍同步。

## 验证交付

- 真实 InnoDB 保持 A 事务时验证无关 B 可完成，同时确认同资源唯一性、资产守恒、失败回滚、重放和截止。
- 输出前后 SQL/事务、编解码次数、字节、耗时与资源证据；P95 必须来自足够且完整的样本，不能从慢日志推算。
- 生命周期变更分开核逻辑负载、表分配量和文件系统可用空间，保留有引用数据。
- 最终记录运行版本、兼容/回退、未覆盖范围和自有资源释放；验收不以测试数量或表数量替代实际行为。
