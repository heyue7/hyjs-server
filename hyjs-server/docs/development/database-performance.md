# 数据库与性能检查

本页解释[后端约定](../../AGENTS.md)中的检查方式，不保存版本与排期。

## 调整前

1. 跟随真实请求定位BEGIN/COMMIT、重复鉴权/存档读取、循环查询及全量序列化；分别统计SQL和事务，保留同输入基线。
2. 识别数据主体、基数、生命周期、冷热和写频率。单个公会设置可随公会标量存储；全局模板与按区服发布快照、余额与流水、当前状态与结算历史各自保留职责。
3. 检查索引是否服务WHERE/JOIN/ORDER BY；合并不能把大JSON/回放带进只取小标量的热请求，不能把高频心跳写带进长期持锁的资产行。

## 实施与验证

- 优先去掉无关工作，再考虑表结构和缓存。事务复用、按需查询、内容未变不写、先过滤有效活动通常可直接降低负载。
- 按项目用户最新要求，单条SQL最多3个JOIN（JOIN数量≤3）；复杂联查改用明确列的批量读取，并同时测往返次数和锁等待。不能把一条联查拆成逐行查询。
- 合并使用有界明确列，写单列/变化列；原唯一性、并发版本、区服隔离及权限保持。需要扩大锁范围时测真实并发，不能只测单线程耗时。
- 回填以数据级哨兵/迁移事实判断完成；覆盖中途退出、重复启动、已被新版本修改的false/零值和旧孤儿行。旧数据不能覆写新选择。
- 压缩核对解压原文/摘要、长度上限和损坏输入拒绝；完成结算保留回执，重复请求不能再次扣费或发奖。
- 清理先核数据库名、表白名单、过期与引用关系；只删可证明无用数据，分批提交，核对资产/历史摘要。表空间回收与整机磁盘变化分别报告，必要备份计入实际占用。
- 日志按价值与频率分级，SQL echo默认关闭；错误/慢请求/必要审计保留。轮转容量与保留期须在部署配置中实际生效。
- 真实MySQL验证迁移/锁/索引和幂等，SQLite仅代表兼容范围。记录输入、环境、测量口径及未覆盖分支；合批后检查运行版本、必要回退及自有资源释放。
