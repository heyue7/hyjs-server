# 文字内容过滤

服务端统一拒绝色情、政治词语，适用于账号名、账号昵称、角色创建/改名，以及世界、场景、私聊、好友留言、公会、公会战文字。语音包附带的文字也检查，音频本身未接入转写审核。

## 方法和来源

- 参考 [houbb/sensitive-word](https://github.com/houbb/sensitive-word) 的 DFA/Trie 与规范化方案，Go 中使用只读 Trie，进程初始化一次。请求阶段不读取文件、不联网、不增加外部服务。
- 分类词表来自 MIT 许可的 [konsheng/Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon)，固定提交 `d967c30b053fa40b06c5a0dddf0be493f2dfae46`：政治类型、反动词库、色情类型、色情词库。其他类别未接入。
- 繁体字映射来自 [OpenCC](https://github.com/BYVoid/OpenCC) 的 `TSCharacters.txt`，固定提交 `9b16591a0d065f5e1121620733721436e83c206f`。使用单字首选映射；未引入词组转换或读音推断。
- `data/sources.json` 保存每个上游原文件的 URL 与 SHA-256；上游原文和许可均随代码保留。`supplement.txt` 为项目补充条目，`exclusions.txt` 仅排除指定词条，无法放行同一句中的其他敏感词。

匹配先做 Unicode NFKC、大小写统一和繁体单字转换，忽略空格、标点、符号、组合标记及零宽字符。接受的原文保持原样。对 `sm`、`sb`、`anal` 三个歧义英文词根使用英文词边界，避免误拦 `smallcat`、`analysis`；其他词语按子串匹配。单字只保留明确的色情字，避免扩大到普通单字。已从通用词库排除“集合、刺激、限量、铃声”等23个明显有正常含义的条目，保护正常组队及游戏用语；较具体的色情词组仍保持拦截。

## 执行边界

- 聊天在事务/回执查询前拒绝，不落聊天记录、不广播、不消耗发送间隔；用户修改后可立即重发。
- 名称校验覆盖注册、旧存储首次登录自动注册、后台建号/创角、账号昵称修改、角色创角/改名与后台改名。密码、已有账号登录、历史名称迁移不参与检查；已有角色创建重试保留原返回。
- 错误提示分别为“内容含有不允许的词语，请修改后再发送”和“名称含有不允许的词语，请重新输入”。不向玩家返回命中词或分类，不记录被拒绝的原文。
- 既有历史消息及名称保持；这是词表匹配，未声称覆盖任意谐音、拼音、图片、音频或上下文语义。误判和漏判通过版本化词表修订处理。

## 维护及验证

修改项目补充/排除词表后，重跑过滤和业务专项，重新构建发布服务端。上游更新时重新固定提交、更新文件/SHA/许可并审查差量；禁止启动时拉取浮动远端词库。

```sh
rtk go test ./utils/contentfilter ./service ./handler -run '^Test(ContentModeration|Contains|Exclusions)' -count=1
```

专项覆盖普通游戏用语、色情/政治及大小写/全角/繁体/插入符号变体、全部发送入口、创角/改名和注册 HTTP 提示、拒绝无写入/无推送/不占冷却及立即纠正发送。数据库场景可使用项目登记的独立 MySQL 库运行 `TestContentModerationChannelNoWritePushOrCooldown`，遵守本机服务分配规则。
